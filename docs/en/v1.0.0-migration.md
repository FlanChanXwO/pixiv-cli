# Migrating to Pixiv CLI v1.0.0

v1.0.0 is the last breaking rewrite of the public Pixiv Go SDK. This guide
covers everything that changes between a v0.x consumer and v1.

## SDK package layout

The old public package `pixiv` is removed. The v1 public surface is:

```text
github.com/FlanChanXwO/pixiv-cli/sdk
github.com/FlanChanXwO/pixiv-cli/sdk/pixiv
github.com/FlanChanXwO/pixiv-cli/sdk/fanbox
```

A single build can only select one version of the root module, so a consumer
switches from v0 `/pixiv` to v1 `/sdk/pixiv` in one change:

```go
// v0
import "github.com/FlanChanXwO/pixiv-cli/pixiv"
client, err := pixiv.NewClient(...)

// v1
import "github.com/FlanChanXwO/pixiv-cli/sdk/pixiv"
client, creds, err := pixiv.Open(ctx, refreshToken) // performs OAuth rotation
```

The old `pixiv` package remains fetchable at its immutable v0 tags; v1 keeps no
compatibility package.

## Authentication

- `pixiv.Open(ctx, refreshToken)` refreshes once and returns a `Client` holding
  only the access token, plus rotated `Credentials`. Persist the rotated refresh
  token before issuing content requests; the Client never refreshes itself.
- `pixiv.New(accessToken)` builds a client for a static token without network
  I/O and without inferring a user ID.
- All content operations require a valid access token. There is no anonymous or
  Web fallback; `web_fallback_enabled` and `PIXIV_WEB_FALLBACK_ENABLED` are
  removed and return `removed_setting` if still present.
- FANBOX is a separate product (`sdk/fanbox`) with its own session credentials;
  Pixiv refresh tokens and FANBOX sessions never convert or fall back to each
  other.

## Local state

Auth moves from `~/.pixiv-cli/auth.json` to `~/.pixiv-cli/pixiv-cli.db` (SQLite).
The CLI migrates `auth.json` automatically once. The default account is stored in
`config.toml` under `[pixiv.auth].default_user_id` and `[fanbox.auth].default_user_id`;
when unset the account with the smallest sort order is used.

## Command and MCP surface

- `pixiv mcp` runs the Pixiv MCP server; `pixiv fanbox mcp` runs an independent
  FANBOX MCP server. They never share clients, cursors, or credentials.
- `pixiv fanbox` adds FANBOX commands: `auth import`, `auth list`, `auth use`,
  `auth remove`, `auth status`, `creators`, `posts`, `tags`, `home`,
  `supporting`, `download`, and `mcp`.
- `pixiv fanbox auth import --from-browser BROWSER` reads the FANBOX session from
  a browser (Chrome/Edge/Firefox/Safari) after online validation.

## Model and output changes

Public models are the v1 `sdk/pixiv` and `sdk/fanbox` types (`Artwork`, `Novel`,
`User`, `Post`, ...). CLI text/JSON/NDJSON output now serializes those models
with stable snake_case keys and a normalized top-level `id` (string), `type`, and
`url`. Media is exposed through `sdk.Resource` (URL + opaque ref); raw upstream
URL fields such as `OriginalURL` are no longer public.
